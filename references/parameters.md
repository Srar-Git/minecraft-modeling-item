# 参数：单位、效果与约束

表中数值是试调起点或明确格式范围；工程中只暴露需要的参数。不要把预设值写进无关模型或自动改掉用户已有值。

|参数|单位/起点|控制与验收|
|---|---|---|
|尺寸、厚度、镶嵌深度|模型单位；常见 Minecraft 16 单位/格|按比例及实际格式；对照侧面、封口、负空间|
|pivot / origin|模型/局部坐标，必须声明空间|同一装配共享运动；不要与 Java 展示中心偏移混用|
|rotation|度；允许范围由 profile 决定|旋转次序与父级需核实，不能用旧限制否定新版或反过来|
|接缝间距|模型单位，无统一 epsilon|先接合或删除共面冗余，再决定需要的间隙；不靠全局 inflate|
|色板|RGBA，按材质分角色|base/light/shadow/accent；保持亮色面积和阴影方向，避免统一压灰|
|纹理尺寸|像素，普通面/小效果先评估16/32|复杂独立图案可增大；单帧、总图集和时间线分开|
|texel density|每模型单位的实际像素|相邻同材质一致；UV 逻辑尺寸与 PNG 尺寸分别读取|
|UV|BB 逻辑空间；Java 通常0..16|像素坐标转逻辑坐标：u=x/PNG宽×逻辑宽，v=y/帧高×逻辑高；动画排布另查|
|outline thickness|模型单位，小亮边0.08–0.25起试|扩大后局部边界合法；不能吃掉窄缝|
|outline layers|通常从1层开始|第二层需明确视觉作用；不默认复制整个模型|
|light_emission|支持版本的整数0..15|最低受光，非 bloom/动态环境灯光|
|shade|布尔|方向明暗；不等同最低受光|
|alpha|PNG 0..255；工具 UI 可能0..1|确认量纲；不透明轮廓通常更稳定，透明需排序检查|
|周期|秒；mcmeta 使用 tick|20 tick/s 的目标纹理更新与视频 fps 分开；重复帧是停留设计|
|幅度/相位|旋转度、位移模型单位；配套预览 phase 以圈为单位|共同部件必须同轨道，独立时钟不能误合并|
|环绕 radius / pitch|模型单位|检查三维前后穿行；沿轴升降要解决循环回位|
|随机 seed|显式整数|控制闪电分支/疏密；重跑可复现，不随机改设计|
|风尾密度/渐隐|角度、alpha、纹理覆盖|以持刀挂点为方向；半径被锁定时只扰动高度或纹理|
|Display transform|slot 的位移/角度/缩放|与几何坐标独立；左右手、GUI、地面逐类检查|

`outline_builder.py` 当前只处理单色 UV 的独立 cuboid 壳，不自动生成渐变和复杂边界。渐变、轮廓边条用 [outline-glow.md](outline-glow.md) 的面方向与边界方法处理。

`preview_runtime.js` 当前支持刚性正弦旋转/位移：`value=offset+amplitude*sin(2π*(seconds/period+phase))`。它可做呼吸、抖动、摆动，不把往复旋转冒称持续绕圈；持续轨道或开合 easing 需按实际项目扩展驱动并做循环测试。

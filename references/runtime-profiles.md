# 目标格式与运行能力

开始前记录：游戏版本、物品/方块/实体、Blockbench format_id、目标导出、动画驱动、是否允许客户端扩展。用户已经给出的信息不重复问。

|目标|合理路径|不能据此承诺|
|---|---|---|
|Java 物品/方块|java_block；几何 JSON＋贴图＋所需 item definition/display|Generic mesh、编辑器骨骼或预览 JS 不会自动运行|
|BetterModel / ModelEngine 玩家或实体特效|对应已安装格式与导出器；保留骨骼/挂点/原动作|本技能的 Java 检查器不认证这些运行时；深入实体动画需专门流程|
|Bedrock / GeckoLib|检测相应格式/插件并按其文档处理|Java 的发光、坐标、材质和动画契约不能照搬|
|Hytale|转对应技能/格式|不能拿其密度与 UV 规则指导 Java 物品|

当前文件审计有明确的历史 profile：

- `java-legacy`：1.21.2–1.21.5 局部预检，单轴、±45°、22.5° 步进。
- `java-1.21.6`：单轴、±45°、连续角度。
- `java-26.1`：多轴/自由角度、sprite 对象；本工具集资源包打包固定核查格式 84。
- `generic`：有限几何结构检查，不认证任意 mesh 或骨骼导出。

其他版本（包括 26.3）不能自动映射到 `java-26.1` 然后称兼容。先查该版本官方说明/导出实现，补充明确 profile 和测试；可在报告中列出现有审计覆盖的共同部分，但不能让它批准未知版本。版本来源见 [sources.md](sources.md)。

`get_capabilities` 只反映编辑器声明。比如 Java 格式的 PBR 编辑开关、纹理 emissive 预览、double-sided 材质，不等于原版客户端使用同名运行字段。

打包器处理已经正确导出的 JSON 和贴图，不负责把预览 JS 翻译成游戏动画。物品状态分帧需明确触发条件；默认持有、右键使用和插件驱动是不同效果，不自行替换。

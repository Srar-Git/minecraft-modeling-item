# 动画、透明与发光

## 选择运行方案

|需求|优先评估|代价或限制|
|---|---|---|
|表面电流、闪烁、火焰形变|16/32 像素单帧 PNG 动画和少量合适方向的面|透明边界、UV 锚点、闪烁频率；薄片侧视问题|
|真实链齿循环、机械振动、环绕粒子|目标运行时的变换/骨骼/实体驱动能力|不能把编辑器预览或 ModelEngine 当作原版物品能力|
|原版资源包内模拟空间运动|在已核实的物品模型选择/变换机制与少量分帧几何之间评估|大量相位几何会增加导出面数，即使贴图透明也不自动免费|

不要把 `transformation` 字段当作通用时间轴。需要时间驱动时确认由什么属性、客户端、插件或服务端机制驱动。不能静默改成另一种运行时来声称保留原版兼容。

分帧遮显方案应估算：静态面 + 每帧动态面×帧数，包含描边壳。编辑器压缩模板可改善操作，但报告必须保留真实展开后的计数。只换 PNG 尺寸不会减少这类几何。

也要区分“把所有相位塞进同一模型，靠透明纹理隐藏”和“物品定义每次只选择一个子模型”：后者可用 `composite` 引用公共静态部分，再由 `range_dispatch` 选择少量运动姿态。同一时刻只绘制选中的姿态，但资源文件、烘焙模型和内存仍有成本。分别报告全部文件保存的元素总数和单个物品同时选中的最大元素数，不能将两者混为一谈。

原版需要右键使用时循环，可在核实版本后评估 `condition: minecraft:using_item` 与数值属性 `minecraft:use_cycle`。后者返回剩余使用 tick 对 `period` 取余；阈值方向需按倒计时推导，普通没有使用动作的物品不会凭空开始循环。少量姿态重用适合开合机构，不能当作任意骨骼动画引擎。参照 [Mojang 1.21.4 物品模型定义](https://www.minecraft.net/fi-fi/article/minecraft-java-edition-1-21-4)。PNG 动画跟随图集时钟，并不自动在开始使用物品时重置；同步要求必须单独验收。

机械联动采用同一个局部变换和枢轴：例如机壳、散热格栅和其下方机件如果是一体，应一起振动。避免把变换反复累加到上一帧；每帧从基准姿态计算。重开文件、暂停/恢复与循环多次后都不得漂走。

环绕采用围绕中心轴的三维轨迹，检查前后穿行及随高度变化；不能只在屏幕平面左右摆动。循环接缝看位置/速度连续性；重置通过不可见相位、缩小或其他已授权表现隐藏。源视频 30 fps 与原版纹理 20 tick/s 应区分，不承诺逐帧等同。

火焰从眼眶/喷口真实出口开始，沿喷出方向延伸并收尖，不能穿过遮挡物。闪电沿表面或边缘路径锚定；改变分支、长度和亮度可用固定随机种子生成可复现帧。不要每次运行随机换设计，也不要所有闪电共用同一个形状和相位。

## 发光的四个概念

需要实际制作亮色轮廓时先读 [描边与外发光实作](outline-glow.md)：包含负尺寸坐标公式、厚度、UV、透明度、组件预算和故障排查。

- **自发亮外观**：支持版本的 `light_emission` 控制元素最低受光等级；`shade:false` 控制方向明暗，二者并非同义。保留暗处可见还要测试 GUI 与实际持有状态。
- **几何描边**：适用时使用略大的倒置外壳，通过背面剔除留下边缘。用户提到“−1”时，检查现有资产中究竟是负缩放、反向尺寸、材质设置还是某插件约定；没有通用的 `outline:-1` 原版 JSON 魔法字段，`inflate=-1` 也不自动等于外发光。
- **bloom 光晕**：是渲染后处理，不由一圈亮色像素或 `light_emission:15` 自动产生。仅按已指定环境采用对应方案。
- **照亮环境**：属于光照系统或动态光扩展，不能用亮色描边冒充。

倒置壳与核心共用变换、枢轴和生命周期，外壳只向外扩张所需厚度。确认导出保留了反向绕序、目标客户端的剔除规则，以及侧面/背面/内部效果；不把负尺寸“修正”为正值。需要上下不同颜色时用明确 UV 色带，避免整体加亮而丢失白→紫等层次。

半透明实体会引入深度排序和过度绘制。Java 26.1 的渲染通道还受整个 sprite 的 alpha 内容影响；将纯不透明的表面和半透明光效混进同一图集可能改变渲染行为。透明、cutout、translucent 分别实测，不借编辑器 double-sided 材质假定游戏结果。

PNG 动画校验帧尺寸、顺序、持续 tick、全部 UV 落点、循环边界及低速/高速播放。单个静止截图不能证明动画、空间轨迹或“丝滑”。

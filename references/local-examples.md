# 可选本地实例与教训

以下实例来自历史工作区中的 `CosmicResource/` 资产目录，仅在当前环境具有对应资产时使用。路径消失时重新定位同名文件，不让技能依赖这些资产。读取模型 JSON、真正引用的 PNG 和 `.mcmeta`，不要只相信文件名或编辑器逻辑分辨率；不复制第三方完整模型/贴图作为技能自带模板。

|检索文件名|已检查到的实现|应学习与保留的边界|
|---|---|---|
|`artificer_blaster.json`|Skills 下 Artificer 包，13 组件，64×64，实体旋转和薄片组合|少量有用斜面，紧凑的表面 UV；部分轮廓是薄片|
|`awakened_shaman_lifescepter.json`|Skills 下 Shaman 包，24 组件，64×64 主纹理和16×16光纹理|某握柄侧面只用2×15像素；多部件有真实角度|
|`awakened_mage_runestaff.json`|Skills 下 Mage 包，38 组件，128×128，30 个零厚度组件|复用 UV 与小装饰有效，但不能夸称全部立体结构|
|`earthen_embrace.bbmodel`|ModelEngine 工程，25 组件，32×32，骨骼关键帧|证明小色板可构成有层次的对象；其动画不能直接等同原版物品|
|`mf_class_witch_weapon_eye.png`|32×416，配套 mcmeta 包含13个图像帧和重复停留|总图高不等于单帧分辨率，不删掉有意重复帧|

本地 `Custom` 的经验：

- 旧冰斧先在4096画布绘图再缩到1024，并以大量扫描切片挤出形状。它保留了细节，但不是应该无条件复用的新模型建造方法。
- 电锯剑蓝刃40切片、活塞48层，说明“少量旋转几何是否能替代”的问题应在建模早期解决；等做完再要求每一处像素和微小轮廓完全不变，重构空间会很小。
- 冰斧的可编辑模板从数千组件减少到974，不代表原版导出同样少；多数动画相位仍展开在资源包里。
- 独立 `frost_rune_axe_rebuilt` 把纯色与动画单帧改为32，原花纹无损重排成512，像素量从2,490,368降到361,472；组件只从974降到958。它是UV/纹理优化，没有完成大幅几何重构，也没有达到截图逐像素完全一致。不能把它作为“所有贴图32、完整重做且完全无损”的成功范例。
- 同一颜色像素搬到另一处图集后，渲染结果仍可能变；需要实际校验，不能只比较PNG颜色集合或整图平均误差。

定位示例（只读）：

```sh
rg --files <CosmicResource目录> -g '*lifescepter.json' -g '*blaster.json' -g '*runestaff.json' -g '*earthen_embrace.bbmodel' -g '*weapon_eye.png.mcmeta'
```

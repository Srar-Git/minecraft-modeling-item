# 低组件建模与保真优化

用于新模型成本设计、既有模型优化和交付前检查。入口的性能硬规则始终适用；本页提供执行方法。历史脚本是特定工程实现，不是可以直接运行在任意模型上的通用优化器。

## 1. 先判断组件为什么多

将模型分解成主体、表面装饰、描边、特效、独立运动装配及时间轨道，逐类统计。先消除表示方式引起的重复，再考虑近似简化。

| 来源 | 优先采用的方法 | 不能丢失的内容 |
|---|---|---|
| 斜面或曲线由密集扫描切片组成 | 合法旋转体块；符合条件的连续表面与侧壁；兼容面的精确合并 | 轮廓、侧面厚度、凹槽、镶嵌、重要分面 |
| 每条刻线、色块都有独立立方体 | 材质细节移入紧凑 UV 图块；相同色板和纹理复用 | 原有立体结构不能误当纯上色删除 |
| 运动部件按每帧复制 | 几何模板＋轨道；刚性组共用变换；目标支持时用骨骼或姿态选择 | 方向、幅度、相位、联动、循环及显示位置 |
| 仅颜色/图案变化却复制几何 | 动画 PNG 和时间线；复用重复画面 | 停留时间、透明度、闪烁节奏、独立时钟 |
| 内部面、完全遮挡组件仍参与导出 | 保守遮挡判定；无贡献组件清理 | 显露时刻、透明孔洞、描边、挂点或其他语义用途 |
| 全模型每个零件都做多层发光壳 | 明确发光对象，使用必要的轮廓壳和边界面 | 外轮廓、凹口、颜色层次和随动关系 |
| 编辑器每帧更新数千对象/UV | 按兼容材质、相位和刚性组缓存预览批次 | 可编辑性、材质顺序、真实父节点与 Display 变换 |

采用某种优化前必须看实际 UV、纹理 alpha、变换和动画数据，不能只看名字或一张截图。

## 2. 开始建模时计算增长量

设静态组件为 S，第 i 条烘焙轨道每个姿态含 Mᵢ 个组件，姿态数为 Fᵢ：

```text
单套可编辑几何 ≈ S + Σ Mᵢ
朴素逐轨道展开 ≈ S + Σ (Mᵢ × Fᵢ)
```

这只是选定表示方式下的数量估算，不是 GPU draw call 或 FPS 公式。若导出器将整个模型或多个轨道状态的笛卡尔积反复复制，成本会更高，必须按真实导出统计。多个姿态文件的总组件数与任意时刻选中的组件数分别报告。

在灰模、批量复制前和导出后检查预算。预算至少包括组件、面、材质/贴图、壳层和帧展开；根据同类成品及目标场景设定，记录预计同时显示的模型数量。没有客户端测量时，预算是工程约束，不是流畅运行保证。

数千组件不是一律损坏，但对于手持武器/道具必须触发成本复审：说明可见结构为何需要这些组件，分别列出被切片和时间复制放大的部分，先验证更紧凑的候选。超预算时不要继续自动扩大帧数、壳数或实例数。修复既有大模型不意味着立即删除其数据。

## 3. 保守优化的顺序

### A. 冻结基线

保存当前实时工程、纹理、动画和导出；记录相机、时间、显示槽位和版本。将本次允许改变的内容和不可改变项分开，候选输出与基线隔离。

### B. 剔除不可见面，再清理无贡献组件

先建立冻结的源几何与材质信息，再计算删除集合，最后统一应用，避免边删边算产生连锁误判。

- 必须证明整张面被同时存在的不透明体积覆盖，局部覆盖不等于可以删除整面。
- 世界变换要可比较；同一个 rotation 数值不保证不同 pivot 下位置一致。
- 自定义轨道、关键帧间插值和独立时钟影响同时性。只检查几个姿态不能证明连续运动中始终被遮挡；无法证明时保留。
- 半透明表面、带孔 cutout、零厚度片和负尺寸壳不能直接当完整遮挡体。未知 alpha/动态纹理不做普通实体推断。
- 被剔除了内部面的封闭实体仍可能代表有效的遮挡体积；必须依据源几何及证明保留这一信息，而不是凭“剩余面数少”或 AABB 猜测。
- 面剔除后检查零可见面组件，确认没有挂点、动画绑定、定位或自定义语义后才删除，并同步维护层级和引用。
- 不用邻接方块的 `cullface` 标记代替手持模型内部面删除。

旧 `optimize_hidden_faces.py` 的已验证范围为相同时间分组、平行不透明 cuboid，且实现仅处理其样例所需的 Z 旋转。旧 `reduce_components.py` 依赖已知工程的相位名字和贴图布局。不能把它们描述为任意 mesh、旋转、材质或动画的通用遮挡求解器。

### C. 精确合并兼容切片

只有几何连接、运动归属、材质、光照/阴影属性、面朝向和 UV 采样均兼容时才能合并。保留外侧端面，删除内部面，不能跨独立骨骼或不同运动轨道合并。

相同贴图 ID 不代表 UV 结果相同；连续 UV 必须保持原映射。色板拉伸只有在整个采样区域确实为同一颜色/alpha、且光照语义不变时才可认为等价，不能拉伸带图案的侧面。UV 镜像、旋转和负尺寸面需单独检查。

坐标发生变化、侧边被拉直或轮廓微台阶被抹掉时，应归类为近似简化。历史冰斧握柄合并用了约 0.02 模型单位的容差；这个数值不是通用默认值，更不能用在用户要求完全不变的任务上。

### D. 替换不合理的表示方式

恒定厚度的切片挤出可以评估“前后可见表面＋连续侧壁”，不必逐扫描线保留一排实体。目标格式需要透明裁形时，分别评估新增图集、cutout 覆盖和材质成本。保留真实侧壁，不把立体握柄或宝石换成单张正面图。

这种重构可能改变边缘光栅化或微小剪影，不能仅凭源贴图未改声称无损。先做小范围候选，用实际渲染判断是否满足任务。

### E. 分离几何与时间

静态主体只保存一次；刚性装配用共同变换驱动；需要独立变形的部分保留独立数据。少量有意义组件的运动，不能默认扩成数十套完整场景对象。

区分三种结果：

1. 可编辑模板压缩：减少工程对象和重复数据，导出可能仍展开。
2. 预览批次缓存：减少编辑器渲染节点和逐帧 CPU 工作，通常不改变游戏文件。
3. 目标运行时的共享几何/姿态选择/骨骼：只有实际支持且导出正确，才可能改变运行时成本。

需要兼容旧的 alpha 分帧几何时，如实保留并报告其成本。透明隐藏的非当前相位不能未经测量就算成“零渲染成本”。不能擅自通过安装客户端扩展、改变触发方式或丢弃动画来完成优化。

### F. 降低编辑器更新成本

在已有原生工具不能解决问题时，预览可按兼容材质、相位和刚性装配合批，缓存几何，逐帧仅更新必要矩阵或纹理帧偏移。透明排序、剔除、纹理采样和光照必须保持；不能为合批强行混合不兼容材质。

源数据变化时使缓存失效，避免每帧重新构建全部对象。选中编辑时恢复真实元素；切项目、暂停、卸载时恢复原矩阵/材质并释放缓存。验证真实项目父节点和 Display，不能只验证一个没有父变换的演示场景。

## 4. 不影响外观的证据要求

按任务要求区分精确优化与近似候选，不能优化完成后自行放宽标准：

- 结构层：保留面上的几何、UV、材质、光照、动画与显示数据对照；变更项提供来源映射。
- 纹理层：未重绘时比较 PNG 字节或解码像素；重排时比较实际映射采样。二者都不能单独替代画面对照。
- 视觉层：固定条件的正背侧、上下、斜视、关键近景和 Display；前景和局部单列，不用空背景平均误差掩盖细节。
- 运动层：循环边界、遮挡变化、联动及轨迹。短离散动画尽量完整采样；长/连续动画报告抽样覆盖，不声称证明全部时刻。
- “完全不变”按现有 `compare_renders.py --strict` 检查所采样图像，并同时保留结构/运动证据。出现差异时先排除相机、时间和渲染条件变化；仍有差异就报告，不自动豁免为边缘噪声。
- 近似候选列出最大几何变化、差异图和受影响部位；用户尚未接受该差异时保留原正式文件。

## 5. 成本报告与交付门槛

交付至少分三栏：

| 对象 | 需要报告的内容 |
|---|---|
| 编辑工程 | 源组件/组、运动模板、预览网格/批次、更新耗时（如实测） |
| 导出资源 | 总组件和面、各状态实际选择的几何、材质、单帧/总纹理像素、壳与透明层、独立动画轨道和展开倍率 |
| 目标运行时 | 实测版本、场景、实例数量、分辨率和帧耗时/FPS；未测则明确未测 |

draw calls 需要实测；模型 JSON 的组件数不能直接当 draw calls。`pixels×4` 仅为基础 RGBA 数据量，不是总显存。纹理更新耗时不等于整帧耗时，编辑器 FPS 不等于游戏 FPS。处于计时器分辨率附近的小数不用于宣称精确提速倍数。

必须处理已证明无用的重复与面，或说明保留理由；检查最终包而非只看编辑工程。无法消除的成本要关联具体造型、效果或目标限制，并记录尝试过的替代。审核通过不依赖统一的“100/500/1000 组件”数字，也不因导出 ZIP 很小就通过。

## 6. 历史依据及边界

以下来自 2026-09-12 的本地记录，2026-10-27 复核报告和对应脚本；没有重新进行客户端性能测试。这些模型只作可选案例，不是技能运行依赖。

| 案例与操作 | 记录结果 | 正确结论 |
|---|---|---|
| 冰斧内部清理＋表面重构 | 7,599→5,855 组件；45,594→31,704 面；1,173 个扫描切片替换为 149 个表面/边条 | 导出几何确实减少；边缘存在变化且新增图集，不能称数学等价 |
| 电锯剑隐藏面剔除 | 31,464→27,416 面，组件仍为 5,244 | 面数减少和组件减少是不同指标 |
| 电锯剑后续剔除＋模板化 | 5,244→697 编辑组件，导出 5,232 组件/27,402 面 | 大幅缩减主要发生在编辑侧；后续报告的 9 张对照样本像素差为 0，不能外推为所有场景证明 |
| 冰斧握柄合并＋模板化 | 5,855→974 编辑组件，导出 5,344；合并 511 个切片，最大轴向表面位移约 0.019705 | 有真实几何缩减，也有模板压缩；不是严格零差异 |
| 万世权杖刚性轨道 | 3,681→156 编辑组件，旧完整动画导出仍为 3,681 | 预览/工程更紧凑；实际 Display 验证曾发现并修正原点混用 |
| 杰斯锤后期制作 | 50 个组件，静态与闪电单帧均 32px，保留开合与两层轮廓 | 说明早期结构选择可以避免大量重复；不是任意武器都必须限制为 50 个 |

# 用少量倒置壳制作描边与外发光

## 从参考画面判断

贴着轮廓、边界清晰、随转动保持形状的一圈亮色，可以直接用 inverted hull（倒置外壳）做出外发光外观。选择这一实现不要求光影包。画面里的模糊扩散、曝光溢出是否还有 bloom，要单独判断；不能凭截图断言作者具体实现。白色核心、青色轮廓、蓝色外层可由实体和一至两层壳构成。

原理：主体挡住壳的远侧中间区域；壳的面绕序反向，开启背面剔除后近侧不画，只在主体轮廓外露出远侧部分。**需要保留单面剔除，不能用双面显示“修复”消失的壳。** 双面显示可能变成覆盖主体的有色盒子。

## Java 立方体的具体做法

先对一个没有旋转的实心长方体试做，确认预览和导出的效果，再应用到复杂组件。使用独立副本，不改变主体 UV。

设主体局部坐标 `from=a`、`to=b`，各轴满足 `b>a`。所需轮廓厚度为 `t`：

```text
outline.from = b + [t,t,t]
outline.to   = a - [t,t,t]
outline.origin   = body.origin
outline.rotation = body.rotation
outline.shade = false
outline.light_emission = 15
```

这里三个轴尺寸变成 `-(原尺寸+2t)`，中心不变，反向绕序保留。用户说的“乘 −1”是**反转尺寸方向**，不是把所有尺寸都直接填成 −1，也不是原版 JSON 有 `outline:-1` 开关。`inflate=-1` 只向内收缩，不能无条件代替上述构造。

例如主体 `[6,22,6]→[10,26,10]`，`t=0.2` 时，壳为 `[10.2,26.2,10.2]→[5.8,21.8,5.8]`。副本与主体放在同一运动组，枢轴和旋转完全一致；不要绕世界原点做负缩放，否则可能移位。

具体 UV：

- 单色壳可将六个面采样同一块小色板，不为每面画一张大图；映射色块内部，避开相邻颜色。
- 直接沿用主体图案时，反转坐标也改变了语义面位置。需按实际世界方向重配相对面 UV 并校对旋转，不能无脑复制面名字。单色壳无需复制主体花纹。
- 渐变描边可以用 16/32px 竖向色带。对旋转面，按世界高度分配 UV 才能保持“下白上紫”等方向；不能假设所有面的 V 都朝上。
- 编辑器纹理的 `render_sides: front`（界面 Outside/正面）配合负尺寸；`double` 不等同最终 Java 剔除结果。纹理预览设置不是原版模型的同名运行字段。

基础数值从组件尺度出发：16 模型单位为一格时，常见小亮边先试 `t=0.08–0.25`；宽亮环可试 `0.3–0.6`。这些是起点，不是格式要求。检查目标距离和最细结构，避免窄缝被厚描边吞掉。壳也须满足目标版本局部坐标范围。

## 亮度、颜色与透明度

`light_emission:15` 用于支持版本中的最低受光等级；`shade:false` 避免朝向造成的深浅变化。亮色材质决定可见颜色，纯黑纹理不会因此变白。它们不会自动给附近方块打光。

Blockbench 5.1.6 的普通预览不会自动把 Java 元素的最低受光值完整重现；其纹理 `emissive` 模式还使用 alpha 参与发亮计算，不等同 Java `light_emission`。不要为了编辑器看起来亮而把游戏 PNG 改成不必要的半透明。可将发亮表面放进一个共用 32px 色板，在项目预览中仅关闭该材质的方向阴影，退出预览时还原；游戏导出仍使用正常颜色/alpha 与合法 light_emission。这个预览设置不能替代暗处客户端测试。

优先用不透明亮色壳获得稳定轮廓：比如白青核心配青蓝壳。若参考确有第二层较淡的硬边光晕，先评估再加**一层**更宽壳；不要默认加三到十层。半透明壳可降低饱和遮挡，但会增加排序和过度绘制风险，不一定比一层不透明壳更像参考。

Java 26.1 的 sprite alpha 会影响渲染通道。将完全不透明的实体与半透明光效分开考虑，查看真实导出引用和客户端效果。`force_translucent` 不能解决所有排序问题。透明平面上的白线描边是纹理边界，不会自动变成立体倒置壳。

想让光效呼吸或闪烁：少量 16/32px 每帧颜色变化即可，几何不必每帧复制。闪电的分叉变化可用独立动画小图，锚定在能源核心附近。壳的透明区不要依赖主体遮挡之外的隐含前提。纯几何扩缩/位置运动仍需目标运行时支持。

## 控制组件数量

只给需要外发光的结构做壳。一个能源立方体通常主体 1 个 + 壳 1 个；需要两圈色阶时再加 1 个。灰金机身的所有铆钉、刻线和内部小块无需各自复制壳。

复杂轮廓可用少量简化壳覆盖主要体积，但必须检查侧面和负空间，不能用一个大盒子包住凹形结构。连续装甲上的平面金色条纹、粗磨损色块、接缝优先放在复用像素贴图中；影响剪影的金属框架、斜角和护圈保留几何。

先统计 `主体 + 轮廓壳 + 特效面 + 运行时展开副本`，再优化。合并编辑器预览网格不算减少导出组件；把每帧位置展开成几十组壳会反向放大成本。

## 故障定位与验收

连续折弧不能逐段无条件套完整壳。双眼权杖的历史问题来自壳伸入相邻凹口，斜视时远近面形成 X。先隐藏各段壳定位，再沿组合轮廓布置边界描边，裁掉连接处无用端面和穿过凹口的侧面；有些内侧窄条只保留正背面。不得因这一案例对所有模型自动删侧面。正视、背视和高低斜视都要复查。

配套 `outline_builder.py` 仅生成/更新独立 cuboid 的单色倒置壳，使用受管理 UUID 映射及独立 `.outline-map.json` 防止重复叠加；重开保存后更新必须携带 sidecar；渐变与复杂轮廓仍按上面的规则处理。参数、输入和导入候选流程见 [脚本操作](tools.md)。

|表现|先检查|
|---|---|
|壳把主体整体涂成蓝色|双面显示、绕序未反转、外壳没有覆盖正确主体、透明排序|
|壳只在一侧出现或从物体移开|中心、枢轴、旋转、父级变换，负缩放是否绕了世界原点|
|轮廓内部交叉/闪烁|重复壳、互相穿插、共面层、没有必要的内部壳面|
|颜色上下颠倒|负尺寸后的面语义与 UV 方向；旋转组件的世界高度|
|编辑器明亮、游戏里变暗|实际导出 light_emission/shade、游戏版本与资源引用；不能只看 BB 预览材质|
|角度改变后成实心方框|开口结构被过度简化，或主体透明而无法遮住远侧壳|

至少检查正面、背面、两侧、斜视、暗/亮环境和不同距离；逐帧确认壳与主体共同运动。结构检查器遇到负尺寸只能提示审阅，不能把 from/to 自动排序。交付时列明壳数量、层数、厚度、颜色、纹理尺寸以及真实客户端是否实测。

公式与单面原理参照 [Outline Creator 作者源码](https://github.com/GitWither/Outline-Creator/blob/master/outline_creator.js)，亮度版本依据见 [sources.md](sources.md)。数值起点和减少组件的方法是制作建议，不能替代目标模型的实测。

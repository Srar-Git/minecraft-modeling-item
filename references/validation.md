# 校验流程

## 先冻结可比较条件

保留基线工程和资产；未保存的实时项目要另存快照，不能假定磁盘文件就是屏幕版本。记录游戏/编辑器版本、格式、渲染器、灯光、背景、相机矩阵与投影、视口大小、对象矩阵、纹理过滤、动画时间/帧号。原图复刻与新旧工程的精确回归是不同验证：不同相机的参考照片不能直接做像素判等。

新建文件有独立文件名、贴图路径和资源标识；按明确范围决定是否独立 namespace。重载工程检查贴图未串用旧文件、父子关系和动画数据持久化。不得用截图替代可编辑模型。

## 四层证据

### 1. 文件与几何

分别对 `.bbmodel` 和实际导出的 Java `.json` 执行 `audit_model.py`。不要只检查编辑组件。

脚本检查：JSON 非有限值/重复键、合法坐标和版本旋转、显式 UV 的纹理逻辑空间、贴图引用/别名/可解析父模型、光照值、PNG 和动画帧元数据。还统计面数、平面、倒置几何、完全重复候选和未旋转同向重合面候选。

`--profile` 必填：

- `java-legacy`：旧版单轴、±45°、22.5° 步进规则；此工具用于 1.21.2–1.21.5 项目的局部结构预检，不是其完整兼容认证。
- `java-1.21.6`：单轴、±45°、连续角度。
- `java-26.1`：允许多轴/自由角度、sprite 对象；不是所有将来版本的通用配置。
- `generic`：只做有限的可编辑立方体结构检查；不能据此批准 Bedrock/ModelEngine/mesh 导出。

`--assets-root` 指向包含 namespace 子目录的 **assets 文件夹**，不要传包根目录。检查报告使用 `.json` 扩展名，存到输入 assets 目录之外。父模型或原版纹理不在输入资产中时报告未解析依赖，不擅自补空白纹理。退出码 0 仅表示本脚本覆盖的规则未发现错误；仍须看 `dependencies_complete`、warnings 和 limitations。

检查器不会自动改变负尺寸壳，不会把薄片当坏方块，也不会按纹理的整张高度将动画判成“大分辨率”。重合面仅供人工定位；材质分层、透明相位等可能合法，不能按候选列表自动删除。

### 2. 视觉

固定条件拍正面、背面、左右侧、上下和代表性斜视，检查识别度、厚度、接缝、凹槽/镶嵌、描边、黑暗与明亮环境、远近像素密度。比较手持、GUI、地面及展示状态；严查关键接缝区域，不能用大面积空背景稀释误差。

`compare_renders.py` 按顶层 PNG 文件名一一匹配，不缩放、不自动对齐、不补缺失文件。提供 `--background R,G,B` 时，报告两幅图前景并集上的误差、变化比例和差异包围框。默认只输出测量，缺文件/大小不同会失败；`--strict` 还要求所有 RGBA 像素完全相同。严格模式包括全透明像素隐藏 RGB，不将“几乎看不出”判成完全相同。

有意义的验收标准来自用户要求和明确目标：

- 完全不变：保存条件一致的严格对照结果；任何非零差异都需如实报告，不能临时放宽阈值。
- 风格重绘/近似复刻：对照关键形状和局部放大，由需求判断容差。没有用户指定阈值时不自动设一个“通过分数”。

只搬原像素但有截图差异时，检查 UV 精度、采样边界、alpha 通道、面朝向及绘制顺序，不先认定某一个原因。

### 3. 动画与运行时

短循环尽量捕获每帧，并检查首尾接缝；较长/程序驱动动画选覆盖关键姿态、遮挡变化、循环边界的样本并说明覆盖范围。并非所有帧都必须不同，停顿/重复帧可能是设计；只有声称持续变化时才检查有无假静止。

验证同一装配的共同变换、粒子三维轨迹、喷射锚点、描边随核心的姿态和缩放、随机分支的可复现性。播放多轮、暂停恢复、保存重开，检查漂移。使用自定义插件/脚本时验证真正导出结果；数据压缩或 UI 预览合批不等于运行时几何删除。

实际客户端可用时：重载包并看日志，在目标版本以第一/第三人称、GUI、地面、暗处、透明背景交错物体测试。未运行客户端就明确写“游戏端未实测”，并只报告实际完成的其他检查；只有静态检查和 Blockbench 对照都确实通过时，才能同时声称这两项通过。

### 4. 成本与交付

分别报告编辑组件、导出组件/声明面数、透明与倒置壳、纹理总像素、每帧尺寸/帧数、材质数。`pixels×4` 只是未压缩基础 RGBA 字节估计，不含 mipmap、atlas 拼接、GPU 对齐和复制，不等于显存实测。性能比较需同场景、同分辨率、同实例数量；资源减少百分比不是 FPS 提升百分比。

检查包根目录、pack 版本、命名空间、模型定义、相对资源引用和 ZIP 完整性；不要硬编码“所有包必须 7 个文件”。再确认用户可打开的主文件和依赖均已保存。

## 工具维护自检

新增文件工具及实机诊断、快照、截图、描边、纹理和打包示例见 [脚本操作](tools.md)。新增脚本不写原模型；原有审计报告仍应放专用输出目录。`audit_cost.py` 要求显式项目预算，缺预算不算通过；对未知动画只记录待审查字段，不推断展开结果。

新工具维护时同时运行 `test_workflow.py` 与 `test_motion.js`。这些测试验证候选写入、拒绝路径、保守剔除、描边幂等、帧序和依赖，不替代 Blockbench/客户端画面。当前 profile 的来源日期及新增工具实测范围见 [sources.md](sources.md)。

```sh
python <skill目录>/scripts/selftest.py
```

测试使用临时目录，覆盖新版多轴与旧版拒绝、边界/光照异常、负尺寸不被修正、贴图缺失/别名循环、逐纹理 UV、动画帧索引、继承模型，以及微小前景错误/渲染缺图/尺寸变化。校验脚本修改后运行；正常低影响模型编辑不必反复运行技能工具自身测试。
